## 二、各模块 DoD（完成定义）与测试实例

**M1 MCP Server**
- DoD：MCP 握手成功；五个工具入参/出参过 schema 校验；意图解析单测（"五一杭州飞成都800以内"→ 正确 route 配置）；E2E：任一 Agent 会话一句话建监控 → snapshot 出现该线路。
- 测试实例：①握手自测脚本 ②意图→config 10 组单测 ③watch_add 写入 config 后 acceptance 全绿。

**M2 源健康自愈**
- DoD：注入模拟故障（改坏端点）后 1 个轮询周期内检出并降级标记；UI 显示降级徽标；生成含候选原因的诊断报告；真实源恢复后自动解除。
- 测试实例：①故障注入单测 ②健康分计算单测 ③诊断报告结构断言。

**M3 反向搜索**
- DoD："¥X 以内从 A 出发"返回目的地列表（含税口径、带数据新鲜度标记）；单次查询总请求数 ≤ 限速预算。
- 测试实例：①预算过滤单测 ②请求预算计数单测 ③API 契约测试。

**M4 洞察周报**
- DoD：周报中每个数字可从 snapshot 重算一致；推送可关闭；语言为自然中文。
- 测试实例：①统计口径单测 ②周报数字与 snapshot 一致性(G4 扩展)。

**M5 插件生态**
- DoD：新数据源只需实现适配器接口 + 通过回放夹具，不改动核心代码。
- 测试实例：①示例适配器过夹具 ②夹具数据与真实响应结构 diff 为空。

## 三、Agent 能力矩阵（谁执行什么意图）

| 用户意图 | 承载模块 | Agent 职责 | 人职责 |
|---|---|---|---|
| "帮我盯着某线路低于 X" | M1 MCP | 解析意图→调 watch_add→回报确认 | 确认配置、接收推送 |
| "接口怎么挂了" | M2 自愈 | 跑诊断探针→定位→给修复建议或自动改 | 审批高风险改动 |
| "X 预算能去哪" | M3 反向搜索 | 组合查询→汇总对比→给建议 | 定夺目的地 |
| "这周价格怎么样" | M4 周报 | 统计分析→写自然语言摘要 | 阅读决策 |
| "加个新数据源" | M5 插件 | 按模板写适配器→过夹具→发 PR | 审查合并 |
| "修 BUG / 加功能" | 本仓库 | 按 AGENTS.md 工作流改码→过验收门 | 验收成果、提需求 |
