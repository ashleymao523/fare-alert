# 部署指南（v0.77）

> 目标：一次部署 = 页面 + 爬虫 + 推送 + 班期库沉淀全部就绪。爬虫循环每天自动沉淀机场班期库（当天+次日两个星期几），连续常驻 7 天后 7 个星期几全覆盖，页面上的起飞时刻从「借周X参考」逐步升级为「班期精查」。

## 形态一：Windows 本机常驻（当前主力）

1. 开机自启：管理员 PowerShell 跑 `tools\register_task.ps1`（计划任务，开机自动拉起 worker 循环）。
2. 手动重启（代码更新后）：`tools\restart_all.ps1`（worker + webui 一起刷新）。
3. 一键升级：`tools\upgrade.ps1`（git pull → npm build → restart_all）。
4. 体检：`python tools/doctor.py`，任何 FAIL 都需要处理，WARN 可接受。

局限：台式机不开机 = 班期库当天断档（对应星期几的精确时刻继续缺）。断档星期几会在下一周同日补上。

## 形态二：Docker 全功能容器（推荐迁移方向）

任何常驻设备（NAS / 旧笔记本 / 小主机 / 树莓派 2G 内存即可，无 GPU 要求）：

    git clone https://github.com/ashleymao523/fare-alert.git
    cd fare-alert
    # 编辑 config.json（路线/阈值/推送），data/ 会自动生成
    docker compose up -d

- 单容器同时跑 webui（:8765）+ 爬虫循环，任一子进程崩溃 3 秒后自动重生。
- `FA_ROLE` 环境变量：`all`（默认，页面+爬虫）| `webui`（仅页面）| `worker`（仅爬虫）。
- 状态都在宿主机卷上（`./data`、`./config.json`）：容器随便删、重建不丢数据。
- `docker logs -f fare-alert` 看双进程合并日志。
- 也可以直接用 ghcr 镜像：`ghcr.io/ashleymao523/fare-alert`（tag 发布自动构建）。

## 形态三：局域网访问 + iPhone 提醒

1. 手机浏览器打开 `http://<设备IP>:8765/v2/`，「添加到主屏」即得 PWA 图标+全屏。
2. iPhone 上装 Bark，把 key 填进 config.json 的 `push.bark_key`，低于阈值自动推送。
3. 远程体检：任意设备 `python tools/doctor.py --url http://<设备IP>:8765`。

## 数据迁移（设备之间搬家）

整个 `data/` 目录 + `config.json` 拷走就是全部状态（快照/班期库/告警历史/缓存/备份）。目标设备放同位置后重启即可。每日自动备份在 `data/auto_backup/`（保留 7 份 zip）。

## 班期库沉淀与时刻覆盖（为什么有些时刻是「借周X」）

- 机场出发/到达板 API 只返回「当天+次日」数据，无日期参数 —— 沉淀是唯一免费路径。
- 每天运行自动存 2 个星期几；连续 7 天常驻 = 7/7 全覆盖。
- 覆盖到的星期几：起飞时刻直接标「班期精查」（灰色 badge）。
- 未覆盖的星期几：同航班号从其他星期几借用，标「借周X参考」（黄色 badge），同航季通常一致。
- 断档补齐后，下轮爬取自动从「借周X」升级为「班期精查」，无需任何手动操作。
