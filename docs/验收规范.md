# 验收规范（G0-G6 门禁）

> 目的：每个模块“搭建完成”必须等于“验收通过”。规范由 `tools/acceptance.py` 执行，
> 文档定义门禁，脚本负责跑分；单测放 `tests/`，DOM 断言放 `tools/ui_check.py`。

## 一、门禁定义

| 门 | 名称 | 内容 | 执行方式 | 何时必须全绿 |
|---|---|---|---|---|
| G0 | 静态门 | 全部 py 可编译、app.js 语法合法 | compileall + node --check | 每次提交 |
| G1 | 单元门 | 核心纯函数单测（税费/学生票/插值/提醒去重/估算价隔离） | python tests/test_core.py | 每次提交 |
| G2 | 接口门 | /api/snapshot 结构契约（routes/deals 字段完整） | acceptance.py 内置检查 | 涉及后端时 |
| G3 | 展示门 | headless DOM 断言 + 截图 | dump_dom.cmd → ui_check.py | 涉及前端时 |
| G4 | 行为门 | 跨层一致性：KPI(cheapest_total) == 真实价最小值；估算价不污染统计 | acceptance.py 内置检查 | 涉及数据/统计时 |
| G5 | 合规门 | config.json 未被 git 跟踪、默认限速 ≥30min、.gitignore 生效 | acceptance.py 内置检查 | 每次提交 |
| G6 | 文档门 | README/使用指南/AGENTS/两份 docs 存在且版本号同步 | acceptance.py 内置检查 | 每次提交 |

状态只有三种：**PASS / FAIL / SKIP**。SKIP 不阻塞但必须注明原因（如 webui 未启动时 G2 跳过）。

## 二、现有测试实例（实例点）

**G1 单测（tests/test_core.py，7 例）**：

1. 含税总价：裸价 400 + 机建 70 + 燃油 50 = 520；日历价含税时不重复加
2. 学生票估算：动车二等座 513.5 × 0.75 ≈ 385.1
3. 插值两侧：day1=100、day5=200 → day3 插值 150，参考航班号取更近邻居
4. 插值单侧回退：只有左邻居时降级为 nearby-ref（offset=2）
5. 估算价隔离：interp/nearby-ref 不进入提醒统计池
6. 提醒去重：同价冷却期内不重复推；降价 ≥5 元且过冷却期才重推
7. below 判定：仅真实价参与阈值判定列表

**G3 DOM 断言（tools/ui_check.py，66+ 项）**：KPI/趋势/日历/列车表/爬虫面板等全量渲染断言，含 v0.11 的 9 项插值断言（徽标、琥珀样式、趋势空心点、最低价仅真实价）。

**G4 活数据一致性**：从 data/snapshot.json 重算真实价最小值，与后端存的 cheapest_total 逐一比对（往返线路跳过，用合计口径）。

**G5 合规实例**：`git ls-files config.json` 必须为空；config.example.json 的 interval_minutes ≥ 30；估算价不得带 alert 标记进推送链路。

## 三、新模块验收用例模板

每个新模块合入前，在路线图对应条目补一张验收卡：

```
模块名: MCP Server
验收门: G0 G1 G2 G4
DoD: MCP 握手成功；工具返回过 schema 校验；E2E：Agent 会话一句话建监控 → snapshot 出现新线路
测试实例: ①tools/mcp 握手自测 ②意图解析→config 单测 ③限速路径单测
```

## 四、FAIL 处理流程

1. 定位：看 acceptance.py 输出的具体 FAIL 行。
2. 先补一个能复现该问题的测试（单测或 DOM 断言），确认它红。
3. 修复代码，让新测试与原有全部门转绿。
4. 提交信息注明修复的门与实例编号。

原则：**没有对应验收实例的功能不算完成；修 BUG 必须先留下复现实例。**
